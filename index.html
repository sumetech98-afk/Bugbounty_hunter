01 · INTRODUCTION

🎯 What Is Bug Bounty Hunting?

Bug bounty hunting is the practice of finding security vulnerabilities in websites, applications, and systems — and getting paid for reporting them responsibly. Companies invite ethical hackers to test their systems, and reward those who find real bugs with cash bounties, swag, or recognition.

It's the ultimate freelance career for ethical hackers. You work when you want, on targets you choose, from anywhere in the world. Top hunters earn $500,000+ per year, and some have earned over $1 million. But more importantly, bug bounty hunting is one of the most effective ways to develop real-world security skills.

In this comprehensive guide, we'll cover everything you need to become a successful bug bounty hunter — from choosing a platform to writing winning reports.

💡 Note: Bug bounty hunting is a marathon, not a sprint. The first few months are about learning. Most successful hunters earn their first bounty after 3–6 months of dedicated practice.
02 · WHAT IS BUG BOUNTY

💰 How Bug Bounties Work

The Basic Flow

  1. Company publishes a program — Defines scope, rules, and rewards.
  2. Hunter finds a vulnerability — In scope, not already reported.
  3. Hunter submits a report — With clear reproduction steps.
  4. Company triages — Validates the vulnerability.
  5. Bounty is awarded — Cash or recognition.
  6. Vulnerability is fixed — Company patches, hunter gets paid.

Types of Programs

🌐

Public Programs

Open to all hunters. Competitive but large scope.

🔒

Private Programs

Invite-only. Less competition, better payouts.

🛡️

VDP (Vulnerability Disclosure)

No pay — recognition only. Good for beginners.

🏢

Self-Hosted

Company runs their own bounty. Common at big tech.

04 · MINDSET

🧠 The Bug Hunter's Mindset

Key Mental Models

  • Think like a developer — What did they forget to secure?
  • Think like an attacker — How would I break this?
  • Think like a user — What's the intended use case? How can I abuse it?
  • Question everything — Trust nothing. Test everything.
  • Be patient — Most time is spent finding, not exploiting.
  • Be persistent — The bug is often one more click away.
  • Be creative — Automation finds the obvious; creativity finds the hidden.

The Hunter's Cycle

Recon → Map Attack Surface → Hypothesize Vulnerabilities ↑ ↓ ↑ Test & Verify ↑ ↓ Report ← Write Up ← Confirm Impact ← Validate Exploit
💡 Reality Check: 90% of your time will be spent on recon and testing. Only 10% on exploiting and reporting. That's normal — the payoff comes from persistence.

07 · RECONNAISSANCE

🔎 Reconnaissance — The Foundation

90% of successful bug bounties come from thorough reconnaissance. The more surface you map, the more bugs you'll find. Recon is where the real advantage is built.

Recon Phases

  1. Subdomain enumeration — Find every possible subdomain.
  2. DNS resolution — Confirm which subdomains are alive.
  3. Port scanning — Discover services on each host.
  4. HTTP probing — Identify web servers, titles, tech stack.
  5. Content discovery — Find hidden directories, files, params.
  6. Historical data — Wayback, Google cache, GitHub leaks.
  7. OSINT — Emails, credentials, API keys, docs.

Full Recon Pipeline

#!/bin/bash # Bug Bounty Recon Pipeline DOMAIN="target.com" OUT="recon_$DOMAIN" mkdir -p $OUT # 1. Subdomain enumeration subfinder -d $DOMAIN -silent > $OUT/subs.txt amass enum -passive -d $DOMAIN >> $OUT/subs.txt assetfinder --subs-only $DOMAIN >> $OUT/subs.txt sort -u $OUT/subs.txt -o $OUT/subs.txt # 2. DNS resolution (find live hosts) cat $OUT/subs.txt | dnsx -silent -a -resp > $OUT/resolved.txt # 3. HTTP probing cat $OUT/subs.txt | httpx -silent -sc -title -td -o $OUT/live.txt # 4. Port scanning naabu -list $OUT/subs.txt -top-ports 1000 -silent > $OUT/ports.txt # 5. URL gathering cat $OUT/subs.txt | gau > $OUT/urls.txt cat $OUT/subs.txt | waybackurls >> $OUT/urls.txt sort -u $OUT/urls.txt -o $OUT/urls.txt # 6. Parameter discovery cat $OUT/urls.txt | grep "=" | qsreplace FUZZ > $OUT/params.txt # 7. Vulnerability scanning cat $OUT/live.txt | nuclei -silent -t cves/ -t exposures/ > $OUT/nuclei.txt echo "[✓] Recon complete. Results in $OUT/"
💡 Pro Tip: Recon is never "done". Always keep looking. New subdomains, forgotten URLs, and leaked credentials appear all the time.

09 · METHODOLOGY

🔄 A Hunter's Methodology

  1. Read the program rules — Scope, exclusions, out-of-scope bugs.
  2. Pick a target — Start with smaller programs to learn.
  3. Recon deeply — Subdomains, URLs, params, JS files, secrets.
  4. Map the attack surface — What endpoints, params, and features exist?
  5. Choose a vulnerability class — Focus on one at a time.
  6. Test systematically — Enumerate all possible injection points.
  7. Verify impact — Prove the bug is real and exploitable.
  8. Document everything — Screenshots, request/response, timestamps.
  9. Write a clear report — Title, severity, steps, impact, PoC, remediation.
  10. Submit and wait — Triage takes days to weeks.
  11. Follow up politely — If no response after 2 weeks, ping again.
  12. Learn from response — Dupes, N/A, or paid — every submission teaches.

Where to Focus First

🔎

Recon

More endpoints = more bugs. This is where you win.

🔐

Login, signup, password reset, 2FA — always buggy.

💳

📡

APIs often have less security than web UIs.

🎯

IDOR

Change IDs, see what happens. Simple but powerful.

📝

JS Files

Read JavaScript — APIs, keys, and endpoints are hidden there.

10 · REPORTING

📝 Writing Winning Reports

A great report gets paid faster, at higher severity, and builds your reputation. A poor report gets closed as "informational" or "N/A".

Report Structure

1. Title → Clear, specific: "SQL Injection in /api/login" 2. Severity → Critical / High / Medium / Low 3. Summary → 1-2 sentence overview of the vulnerability 4. Steps to Reproduce → Numbered, precise, copy-paste commands 5. Proof of Concept → Screenshots, HTTP requests, output 6. Impact → What can an attacker do? Be specific. 7. Remediation → How to fix it (prepared statements, etc.) 8. References → OWASP, CWE, CVE links

Winning Report Tips

  • Be concise — Triagers read hundreds of reports.
  • Show the impact — Don't just prove it works, prove why it matters.
  • Use curl commands — Copy-paste reproduction is fastest.
  • Include screenshots — Visual evidence speeds triage.
  • Suggest the fix — Shows expertise; gets higher severity.
  • Don't exaggerate — False claims hurt your reputation.
  • Follow up politely — After 2 weeks if no response.
💡 Pro Tip: A well-written report for a Medium bug often gets paid faster than a poorly-written Critical. Quality matters.

13 · BEST PRACTICES

✅ Bug Bounty Best Practices

  1. Read the rules first — Scope, out-of-scope, and testing restrictions.
  2. Never test without authorization — Even a simple scan can be illegal.
  3. Don't cause damage — No DoS, no data destruction, no service disruption.
  4. Be patient with triage — Responses take days to weeks.
  5. Don't spam duplicates — Same bug in 50 URLs = 1 report.
  6. Report quality > quantity — One great report beats ten poor ones.
  7. Don't disclose without permission — Wait for the fix.
  8. Learn from rejections — Each "N/A" teaches something.
  9. Build relationships — Triagers remember good reporters.
  10. Stay humble — Every hunter started where you are.
14 · LEGAL & ETHICS

⚖️ Legal & Ethical Boundaries

⚠️ Critical Warning: Bug bounty hunting is only legal when you follow the program's rules exactly. Testing outside scope, even on a "related" asset, is illegal and can result in criminal charges.

Golden Rules

  • Only test in-scope assets — Never stray from the defined scope.
  • Follow the program rules — Every program has specific rules.
  • Don't access user data — If you find it, report it — don't download it.
  • Don't disrupt services — No DoS, no data modification, no crashes.
  • Report immediately — Critical bugs should be disclosed fast.
  • Don't disclose publicly — Until the company fixes the bug.
  • Respect rate limits — Don't hammer APIs or endpoints.
  • Use test accounts — Never test with real user accounts.
💡 Legal Framework: Bug bounty programs act as authorized penetration testing contracts. As long as you stay in scope and follow the rules, you're legally protected. Step outside, and you're on your own.
15 · CONCLUSION

🎓 Final Thoughts

Bug bounty hunting is one of the most rewarding careers in cybersecurity. It offers freedom, challenge, and serious money — but it also demands patience, discipline, and continuous learning. There's no shortcut. The hunters at the top of the leaderboards have spent years honing their craft.

The good news: the path is clear. Master the fundamentals, build a solid recon pipeline, study disclosed reports, and practice relentlessly. Your first bounty will feel like a milestone — because it is. Everything after that compounds.

Your 90-Day Action Plan

  1. Week 1-2: Complete PortSwigger Web Security Academy labs.
  2. Week 3-4: Build a recon pipeline with subfinder, httpx, nuclei.
  3. Week 5-6: Pick a VDP program on HackerOne and hunt for 2 weeks.
  4. Week 7-8: Study 20 disclosed reports. Understand why they were valid.
  5. Week 9-10: Focus on one vuln type (IDOR or XSS). Hunt 4 hours/day.
  6. Week 11-12: Submit your first report. Learn from the response.
🚀 Remember: Every top hunter was once a beginner. The only difference is they never stopped. Start today, stay consistent, and the bounties will come.

Happy hunting — ethically. 🎯
